# Personalization

Respect the user's explicit language, formal/friendly tone, brevity/detail, technical background, learning interests, working pace, and confirmation preferences. Ask a few relevant questions, not a long survey. Do not infer sensitive traits.

## Private and shared

With consent use templates/USER_PREFERENCES.example.md to create .portal/user-preferences.local.md. It is outside the website and Git-ignored, not an encrypted vault or cross-device account.

Shared team norms belong in approved project instructions. Never publish private chats/preferences in portal pages.

## Style versus reality

Friendliness cannot justify invented facts; speed cannot authorize destructive changes or skipped checks. Current requests override stale saved preferences.

The starter website is English. An assistant can translate content and set UI language; no full automatic translation system is included.
